# Theresia V1.2（封存版）

MCUG Launcher 的第三方前端：整体替换启动器界面。**只改前端显示，不动内核、不加后端功能。**

- **包名**：`com.theresia.mcugl`
- **显示名**：`Theresia V1.2`
- **版本**：`1.2.0`
- **内核契约**：`mcugl.kernel/v1`（`^1.0.0`）
- **产物**：`release/com.theresia.mcugl-1.2.0.mcuglf`
- **sha256**：`e753256338608ea3fb4a689a08091069c9b0f8b32f15873874e43173995ffbff`

## 0. 目录边界

```
MCUGLauncher-M/
├─ src/            官方内置界面（原版，随 tauri build 打包进二进制）
├─ src-tauri/      桌面端内核（Rust）——本项目不改这里
├─ theresia-v1/    1.0.0 归档
├─ theresia-v1.1/  1.1.0 归档
└─ theresia-v1.2/  ← 本工程：最终版，所有 UI 代码在这里
```

三个 Theresia 目录共用同一个 `identifier`，启动器按 semver 取最新版本（1.2.0）。
旧目录只留 `release/` 里的成品包和 README，源码在 git 历史里。

## 1. 它是什么

启动器支持在运行时把整个前端换成第三方实现（目录或 `.mcuglf` 包）。Theresia V1.2 就是这份实现：

- 页面、样式、交互全部重写，官方内置界面完全不加载；
- 通过 `window.__TAURI_INTERNALS__.invoke` 调用与官方界面**完全相同**的命令，读实例、账号、设置、启动游戏的权限一致；
- 因为不编译 Rust，界面迭代只需要重建前端、刷新窗口（目录模式）或重装包（分发包模式）。

## 3. 构建与预览

```powershell
cd theresia-v1.2

npm install          # 首次
npm run dev:demo     # 浏览器预览，端口 5176，用内存假数据
npm run build        # 构建 → dist/（根目录自带 frontend.json）
npm run pack         # 打包 → release/<identifier>-<version>.mcuglf
```

> `release/` 里的文件名带版本号，升版本时同步改 `package.json` 的 `pack` 参数与 `frontend.json` 的 `version`。

仓库根也有转发命令：`npm run v1.2:install` / `v1.2:dev` / `v1.2:build` / `v1.2:pack`。

> 预览不需要 Rust：`--mode demo` 会注入演示后端，界面走 `src/demo` 的假数据，行为与正式环境一致。

## 4. 安装与启用

三种方式，任选其一：

1. **拖动安装（推荐）**：启动器 → 设置 → 开发者选项 → 把 `release/com.theresia.mcugl-1.2.0.mcuglf` 拖进虚线框。松手后自动完成「安装 → 启用 → 重启界面」。
2. **按钮导入**：同一张卡片里点「导入前端包…」→ 列表里点「使用」→ 点「重启前端」。
3. **开发目录**：把 `MCUGL_FRONTEND` 指向 `dist/` 或 `.mcuglf` 绝对路径后启动，改完文件刷新窗口即生效。

加载优先级：`MCUGL_FRONTEND` > 设置里选中且已安装的前端 > 官方内置界面。

**停用**切回官方；**卸载**删除该版本（若是当前启用项，自动切回官方）。
**逃生**：界面白屏或卡死时按 `Ctrl+Alt+C`，启动器清空第三方前端选择并原地重建窗口。

## 5. 前端包规格

| 字段 | 值 | 规则 |
| --- | --- | --- |
| `identifier` | `com.theresia.mcugl` | 反向域名，≤ 128 字符 |
| `name` | `Theresia V1.2` | 显示名 |
| `version` | `1.2.0` | semver |
| `kernelApi` | `^1.0.0` | 必须匹配启动器内核 `apiVersion` |
| `entry` | `index.html` | 包内相对路径，文件必须存在 |

包体约束：单文件 ≤ 128 MiB、总解压 ≤ 256 MiB、条目 ≤ 2048、仅 store/deflate。
当前包 8 个条目、约 203 KiB。

## 6. 与官方界面的差异

| 维度 | 官方界面 | Theresia V1.2 |
| --- | --- | --- |
| 导航 | 顶部胶囊（5 项） | 同结构，选中项为主色浅底，图标随主色着色 |
| 首页 | 壁纸 + 右下三张卡 | **纯色底** + 左侧**实例轨道** + 右下**启动坞** |
| 主题 | 固定蓝白 | **16 套主色** + **明暗双模式** |
| 设置 | 单卡片堆叠 | 左标签右控件的行式布局 + 保存条 + 常用值 chips |
| 账户 | 右上角「添加账号」按钮 | 列表末尾的**虚线加号卡**（网格卡片尺寸，跟随主色） |
| 服务器 | 四个同权重文字按钮 | 卡片重构：状态徽标 / 可复制地址 / 实例 chip / 主操作 + 溢出菜单 / 就地删除确认 |
| 状态入口 | 右上角单一入口 | 左下角**实例灯**（红/绿/数字）+ **下载进度三角**（红填充 → 翻绿 → 消失） |
| 窗口拖动 | —— | 顶部导航带兼作无边框窗口拖动区 |

## 7. 开发者选项里的预览开关

以下开关**只影响界面显示**，不会触发任何后端行为，也不写入正式配置（存 sessionStorage，重启即恢复）：

| 开关 | 作用 |
| --- | --- |
| 强制显示下载任务按钮 | 没有任务时也让下载入口常驻，方便调样式 |
| 强制播放下载动画 | 0→100 循环播放「红填充 → 翻正变绿 → 消失」 |
| 实例状态灯预览 | 固定成 0 / 1 / 2 个运行实例（红屏 / 绿屏 / 绿屏带数字） |
| 服务器状态预览 | 固定成 在线 / 离线 / 查询中 三种卡片状态 |

## 8. 已知限制

- 主题偏好只落本地 `localStorage`（键 `mcugl.theme.v1`），未写入启动器配置；
- 内核的 `ping_server` 目前返回 `unsupported`，服务器状态在真实环境里恒为「离线」；本版**不补后端**，只用开发者选项的预览对比三种状态；
- 部分深层页面沿用官方版的布局骨架，只替换了设计令牌，尚未逐屏重做。

## 9. 排错

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 拖入后没反应 | 不是 `.mcuglf` / `.zip` | 只有这两种会被安装 |
| 导入报 `VALIDATION_ERROR` | 清单字段不合规 / `entry` 不存在 / `kernelApi` 不匹配 | 对照第 5 节逐项核对 |
| 界面白屏 | 前端运行时异常 | 按 `Ctrl+Alt+C` 切回官方，再看「运行日志」 |
| 停用后仍显示 Theresia | 浏览器演示模式不会真的重载 | 正式环境由内核重建窗口 |
